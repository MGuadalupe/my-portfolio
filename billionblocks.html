Case study · Billionhands · 2025

BillionBlocks

Designing and engineering a design system with AI.

From a visual audit of a product with no tokens and no documentation, to an accessible system inside the company repo with an AI copilot, a documentation site and an agent that generates interfaces using only the system.

Role
Product Designer → Design Engineer
Company
Billionhands
Scope

Tools
Figma · Figma MCP · Custom GPTs · Pencil · Vercel
00 — The beginning

When I joined Billionhands, the product was growing, but the interface lacked a solid systemic foundation. UI decisions were functional but not structured. There was no formal design system, no tokens, and no shared documentation between design and development. So I decided to create Billion Blocks.

What began as a visual audit evolved into the complete creation of an accessible, scalable design system, directly integrated into the company’s repository.

My role evolved from Product Designer to Design Engineer as I expanded my practice with AI building agents that generate design and production-ready code from the system.

01 — Audit

Find the problem before designing.

Before designing any components, I audited the live platform to understand what was working, what wasn’t, and the underlying issues.

Issues detected
  • Inconsistent spacing and typography
  • Colors without contrast validation
  • Components with unclear state definitions
  • Hardcoded values in code
  • Repeated but unstandardized patternsno guide to follow for new use cases
  • Total lack of documentation
Impact
  • Constant rework
  • Visual bugs
  • Accumulated design debt
  • Difficulty scaling new features
  • A significant gap between what was in production and what was designed
What I analysed
Typographic hierarchies Actual colour usage Spacing and structural consistency Interaction patterns Incomplete or missing states Contrast under WCAG

This analysis allowed me to identify systemic inconsistencies and define real priorities, instead of “redesigning by intuition.”

02 — Foundations

Accessible from the outset.

Color system

I tested multiple palettes, prioritising accessibility from the start. There was an initial palette, so I audited every colour and adjusted its shades to guarantee contrast and legibility.

Contrast was validated not only in default, but across every interactive state:

Default Hover Active Focus Disabled Loading

Token inventory

There are conventions for building a token inventory but Billionhands already existed and had been built without a design system. So I aligned with the development team, pulled the repository and studied how they had structured the CSS classes.

With that in mind, I built a solid token library fully aligned with the frontend.

--bb-primary-basebrand/red/500
--bb-primary-strongbrand/red/900
--bb-neutral-strongbrand/neutral/500
--bb-neutral-basebrand/neutral/800

Typography

I defined new font sizes aligned with accessibility standards, and patterns for when to use each size.

03 — AI as a copilot

Meet Patty, my design system copilot.

It was time to document everything and keep advancing the system. Following the traditional process, this would have taken months so why not leverage the tools already at our fingertips?

I created Custom GPTs specialised in design-systems engineering, whose main job was to audit every step I took building Billion Blocks.

The golden rule

Billion Blocks could not be the single source of truth.

So Patty could audit any change or new feature, every decision had to be cross-checked against mature systems:

Material Design Carbon Shopify Polaris Atlassian

This turned AI into a strategic validation layer, not just an operational one.

04 — AI-driven documentation

Documentation as a stress test.

With the foundations defined, I needed real adoption and consistency. I built the design system website with the Figma MCP, under one clear restriction:

The model could only use existing components and tokens. No new styles could be created.

If the MCP needed something that didn’t exist, the problem was with the system not the model.

AVisualising foundations
BDocumenting components
CShowing accessible states
DAligning design and development

But above all: validating that the system was truly usable.

05 — Billion Blocks agent

Generating UI with only the system.

Once defined and documented, could the system actually accelerate product creation? I used Pencil, an AI interface-generation tool, with a clear restriction: every interface had to be generated exclusively from the design system.

Pixel-perfect, production-ready designs without pulling in development resources.

✓ componentsReuses components from the design system
✓ patternsFollows the patterns established with Patty
✓ tokens onlyNo fixed values, every variable is a token
! reports gapsFlags missing tokens and inconsistencies

The agent lives inside the Billionhands repository and became a key tool in the company’s product workflow.

06 — Outcome

From visual guide to product-generation infrastructure.

Strategic outcome

The combination of three pieces enabled the rapid, consistent creation of new interfaces aligned with the system:

02Accessible documentation
